# Data sent to models and stored in evidence

LLM providers are opt-in. Configuring a provider may transmit task titles and descriptions, intake chat history, draft requirements, project summaries, selected repository file text/diffs, review rules, CI log excerpts, acceptance criteria and intermediate model results to that provider's configured HTTPS endpoint. Reviewers/judges/fallback providers may receive the same material. This is not a local-only confidentiality guarantee. GitHub offline/dry-run flags are not an LLM egress control. Leave provider keys/base URL unset for offline tests; tests use mock HTTP.

The shared provider boundary scrubs registered credential values and recognized token patterns from message contents, including persona and retry feedback, before serialization. Credentials used to authorize the provider remain only in its Authorization header. This is a limited filter: unknown secrets, personal data, proprietary code and business content may remain. Obtain permission before sending a repository's contents to a model and check provider retention/processing terms yourself.

Audit payloads and evidence string leaves are scrubbed before canonical serialization and hashing. Thus API reads of these newly written payloads expose the scrubbed records and their matching integrity hashes. Existing records are not rewritten. Task bodies, intake chats, drafts, settings and other application tables can still contain user-supplied sensitive data; do not enter credentials in task/chat text and do not treat API exports as anonymized datasets. Integration credential APIs expose metadata/masked status, not raw stored tokens. Authentication and workspace/role checks protect access, but authorized workspace members may see task/evidence content.

Audit/evidence integrity is append-only; there is no complete personal-data retention/erasure workflow in this experimental version. Restrict data volumes, logs and backups. SMTP sends configured notification summaries and recipient addresses to the chosen mail provider. Review all exported JSON, screenshots and logs before sharing them. No scanner or filter proves that data cannot leak.
