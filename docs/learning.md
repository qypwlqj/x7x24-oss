# 学习闭环 MVP 使用与边界

本版实现设计中的阶段 A 与 B：整理交付过程、产生返修策略候选、固定用例的成对重跑、密封审计、小范围分配与撤销。没有完成改进器自身的递归优化，也没有宣称实际交付收益。设计见 [RSI 方案](design/recursive-self-improvement.md)，研究见 [一手资料](rsi-primary-sources.md)。

## 默认行为与启用

默认 `LEARNING_ENABLED=false`、`LEARNING_MODEL_ENABLED=false`。数据库迁移创建学习数据表；默认不整理样本、不调用优化模型、不改变交付策略。

开启 `LEARNING_ENABLED=true` 后，每分钟按项目整理已结束的执行记录，也可以手动触发。v1/v2 阶段执行与 v3 节点运行均可整理；缺少代码版本、完整材料或实际验收的记录保留 UNKNOWN/INCOMPLETE，不自动成为可重跑用例。投影每批最多 200 条阶段记录及 200 条节点记录，定时作业每次处理至多 100 个活跃项目。

只有管理员主动调用候选生成/评测接口，且 `LEARNING_MODEL_ENABLED=true`，才会产生模型调用。模型与角色使用项目当前 dev.fix 的配置；延用已有供应商与外发授权，不添加新供应商。两种环境变量均不构成真实 GitHub 写操作的授权。

费用使用供应商配置的估算价格。`LEARNING_MAX_CALL_USD` 限制包含重试与备用路由的单次预估；`LEARNING_DAILY_USD` 限制每项目每日学习费用。学习费用、失败调用与评测分钟写入原预算账本，同时遵守项目、产品线和工作区预算。付费调用先预留费用及 Token；无法确认用量的异常保留 UNKNOWN 预留，不将其释放为零成本。

## 独立实验环境

`FILE_ASSERTIONS` 执行文本/JSON 断言，适合调试闭环。这个范围不能通过真实任务试用条件。

`PROJECT_TESTS` 额外执行服务端固定的项目测试命令。需先部署独立 Docker 运行资源，并设置：

- `LEARNING_DOCKER_IMAGE`：必须是含 `@sha256:` 的固定镜像摘要。
- `LEARNING_TEST_COMMAND`：管理员配置的项目测试命令，例如已准备好依赖的项目使用其标准测试入口。
- `LEARNING_TEST_TIMEOUT_SECONDS`：1–300 秒，默认 30。

镜像应事先包含离线构建/测试所需工具与依赖。每个 arm 在新目录中写入固定输入与模型补丁；容器无网络、无生产凭据、无宿主 socket 或共享缓存，限制内存/CPU/进程数，根文件系统只读，临时目录有界。候选不能更改固定测试、锁文件和治理文件。命令超时或运行器不可用时不得晋级。命令与镜像改变后必须创建新评测集。

“项目测试”指配置的命令和声明的独立断言所覆盖的范围，仍需项目负责人保证命令确实运行所需检查；不代表覆盖所有业务场景。本版没有在真实模型、真实目标仓库或真实 Docker 环境完成效果实验。

## 接口顺序

所有接口沿用登录和 `X-Workspace` 工作区选择。读取可供当前工作区成员使用；所有写操作要求工作区管理员，并校验项目归属。

| 操作 | 接口 |
| --- | --- |
| 查看样本、候选、实验、发布与评测集摘要 | `GET /api/projects/{projectId}/learning` |
| 手动整理历史执行 | `POST /api/projects/{projectId}/learning/project` |
| 登记固定评测集 | `POST /api/projects/{projectId}/learning/suites` |
| 生成候选 | `POST /api/projects/{projectId}/learning/propose`，正文 `{"suiteId":"...","count":1}` |
| 验证集对照 | `POST /api/projects/{projectId}/learning/policies/{id}/evaluate`，正文 `{"split":"VALIDATION"}` |
| 密封测试 | 同上，正文 `{"split":"TEST"}` |
| 发布记录/撤销 | `POST /api/projects/{projectId}/learning/policies/{id}/release` |

评测集正文示例形状如下；实际需要包含三个分组的多个用例：

```json
{
  "name": "某项目返修基准第 1 轮",
  "scope": "FILE_ASSERTIONS",
  "cases": [{
    "id": "case-001",
    "rootTaskId": "原始根任务 ID 或外部基准用例 ID",
    "family": "独立故障族标识",
    "split": "DISCOVERY",
    "baseSha": "尝试前的固定代码版本",
    "goal": "修复输入处理",
    "failure": "可复现失败摘要",
    "files": {"src/value.json": "{\"value\":0}"},
    "editablePaths": ["src/value.json"],
    "checks": [{"path":"src/value.json","kind":"JSON_EQUALS","expected":"{\"value\":1}"}]
  }]
}
```

`split` 为 DISCOVERY、VALIDATION 或 TEST。相同 rootTaskId 或 family 不能跨组。每个分组至少一个用例，每个评测集最多 150 个用例；每个用例最多 100 个文本文件、总计 20 万字符，模型输入另受上下文预算约束。断言类型支持 CONTAINS、EXACT、JSON_EQUALS。验证命令以外的断言保存在评估端，不发送给模型。固定代码和测试应从已核验版本导出，不能把最终修复答案当作尝试前输入。

每轮最多生成 5 个候选；提案只能修改返修指令，保存假设、来源 episode 与生成模型配置。经验卡保持 PROPOSED，它的效果需结合候选实验/发布判断，不自动转成通用知识。

## 评测与发布规则

新旧策略针对相同用例，随机决定一对内的执行顺序，采用相同模型配置；每个 arm 都重新产生补丁并执行独立评估。试验记录模型、费用、Token、耗时、证据摘要与失败状态。

验证集通过后才允许密封审计；一个评测集只能为一个候选开启密封测试，打开后不能继续提案或搜索其他候选。同一候选/分组重复请求返回原实验，崩溃或未知运行不自动重复付费执行，需要核对后建立新一轮。

当前真实试用条件同时要求：

- 范围为 PROJECT_TESTS；验证与密封测试各至少 20 个独立用例（配置只能调高）。
- 无执行错误、无旧策略通过而候选失败的回归、实际模型与配置可比。
- 至少 5 个候选独立修好的用例；零反向结果时，配对符号检验的单侧概率至多 1/32。
- 候选运行费用不超过基线的 110%。生成费用单独报告，不能据此直接宣称经济回报为正。

这是一个适合首版大幅改善筛选的保守规则，不能用于证明几个百分点的小收益，也没有替代后续真实任务及延迟质量观察。

发布正文为 `{"state":"SHADOW","percentage":0,"reason":"隔离观察"}`，或在通过审计后用 CANARY、1–10 的 percentage。SHADOW 仅留观察记录。真实任务稳定分流，进入返修时保存一次版本选择，后续重试固定该版本；只有创建时间不早于发布的新任务可参与。

撤销使用 `{"state":"REVOKED","percentage":0,"reason":"发现反例"}`。已撤销版本不能重新启用，在途已分配任务再次执行时会停止，要求核对恢复方式。

本版不会自动进入 ACTIVE，不提供对上线收益的自动判断或第二层改进器晋级。首次真实试用仍需要后续验收数据；没有这些数据时保持试用/实验状态。

## 当前覆盖范围

- 过程采集覆盖 v1/v2 和 v3；历史记录不改写、不补造实际模型/测试结果。
- 新策略接入 v1/v2 的 legacy-json 返修指令路径，并为实际派发记录策略版本与结果观察；规则执行器不注入策略。schema3 的角色/输入指纹和 remote-docker 的独立实验适配需要后续扩展，本版不向这两条路径注入新策略，也拒绝在远程模式启用试用。
- 查询接口只返回评测集摘要和实验汇总，不暴露密封断言或逐例密封反馈。
- 本版为后端闭环，尚未增加专用前端页面。
- 默认离线验证使用模拟模型与明确标注的测试执行器；它证明流程约束工作，不证明真实模型质量提升。

## 验证

后端标准检查为 `mvn verify`。macOS 上现有本地执行器会拒绝经过符号链接的临时目录，可在启动测试 JVM 时指定真实路径：`mvn -DargLine=-Djava.io.tmpdir=/private/tmp verify`。新增学习测试使用独立内存数据库，避免将其他测试积累的历史样本误当成当前用例。
