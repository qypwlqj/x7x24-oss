# Minimum permissions

Start offline with dry-run enabled and no real credentials. Authentication, workspace membership/roles and PostgreSQL RLS remain separate boundaries. An empty platform admin list grants no platform administrators. Workspace owner/admin roles do not grant platform-wide administration.

For sign-in, use your own GitHub App and restrict permitted logins and browser origins. A public OAuth Client ID identifies an app; it is not a secret. Store its Client Secret and encryption key only in protected deployment configuration.

For repository integration, select only the intended repositories. Begin with metadata/contents/issues/pull requests/actions read access needed for discovery and diagnostics. Grant write permissions only for individually authorized functionality (contents/PR/issues/actions; releases also require contents write). Avoid account-wide classic PATs. Do not grant workflow-file modification, administration, organization or package permissions just for reading a project. GitHub's granted app/PAT scopes and repository rules must independently constrain what the service can do.

An existing empty repository can be initialized through the task action “初始化仓库并继续”. Members may propose it; a workspace owner/admin must confirm the repository, target branch, fixed README content and commit message. The project setting `autoInitializeRepository` (off by default, editable only by managers) authorizes the same controlled operation before development. Current authorization overrides task snapshots, so revocation takes effect immediately. This uses GitHub's Contents API with Contents write permission, requires the project's target branch to match GitHub's default branch, and creates only `README.md`. It does not grant ordinary pushes to `main`, change repository rules, or create a new GitHub repository. A repository-scoped operation journal deduplicates concurrent tasks. Unknown results are reconciled against the marked root commit and its immutable README; missing proof never triggers another write. If an external actor races the first commit, processing stops for reconciliation instead of overwriting or rolling back their work. Initialization supplies a baseline; dependencies and CI still follow their existing policies.

`ADAPTER_DRY_RUN=true` reduces external write operations; it is not a substitute for permissions or data review. Real mode can still read remote repositories. Configured LLM requests and SMTP notifications can leave the machine even while GitHub writes are disabled. Use no LLM/SMTP keys for offline verification. See [data policy](data-policy.md).

Use a non-superuser, non-BYPASSRLS PostgreSQL application role. Restrict schema/database/network access and verify RLS on the actual installation. System/background operations intentionally use unscoped database sessions; direct database access is privileged and is not made safe by a workspace header.
