# 产品线、项目与交付任务

产品线管理业务目标和治理；项目连接实际仓库并提供技术上下文；任务归属项目，在交付流水线中流转。一次节点执行记录输入、结果、错误、证据和成本。同一任务不会因为返修而变成另一项任务。

## 页面使用

1. 打开「产品线与项目」，点击「新增产品线」，填写名称、业务目标、负责人和预算。新产品线默认 L1；LMS 一般业务代码需要产品线及项目均允许 L2。
2. 在产品线内点击「新增项目」，填写 GitHub 仓库、目标分支和 CI 文件。一个未归档项目绑定一个仓库；暂停项目仍保留仓库归属。
3. LMS 使用 `example-owner/example-project`，选择「React + Go」预设，确认 `frontend` / `backend` 模块、测试方式和允许修改的目录。预设不创建或修改 LMS 仓库的 CI 文件。
4. 进入项目，使用「测试连接」校验仓库、分支和 CI；使用「新增任务」填写问题和验收标准。真实适配器模式下同步创建 Issue，离线模式只保存本地任务。
5. 总览和任务列表可以按产品线、项目联动筛选。项目流水线点击节点打开该项目的任务，任务详情查看节点执行记录和完整历史。

## 需求发现

项目支持手动扫描及定时扫描；定时扫描默认关闭。源码分析需要配置 LLM，通过项目目录及文件类型限制读取有限文件并轮换扫描范围，并核对模型引用的原文确实存在。主干测试失败来自配置的 GitHub Actions 工作流，扫描不会主动启动 CI。错误日志可以从项目页面或接口导入，已登记密钥先脱敏。

重复问题更新候选的出现次数和证据，不重复生成任务。「低风险候选自动进入任务池」默认关闭；开启后，仅低风险候选自动转换，之后仍经过现有 PRD、开发、测试和验收闸门。其他候选可查看证据后转为任务或忽略。日志导入不代表已完成错误复现。

源码扫描和实际 React / Go 代码修改需要服务器配置 LLM；无 LLM 时保留现有确定性规则执行器，其通用业务开发能力有限。GitHub 凭据仍从服务器的 `GITHUB_TOKEN` 环境变量读取，项目配置只保存凭据引用。

## 隔离和生命周期

- 任务的产品线由所属项目确定，不能单独指定其他产品线。第一版不支持移动项目到其他产品线。
- 全局、产品线、项目、任务逐级限制执行。项目不能突破上层禁止项、自治等级和预算。每笔费用只记一次，分别聚合到任务、项目、产品线。
- 技术配置记录在任务启动时的版本快照中。当前收紧的路径和自治限制即时生效。有未结束任务时不能切换项目仓库、目标分支或凭据引用。
- 产品线或项目暂停后不再准入和调度新步骤；真实 GitHub 写操作再次检查暂停和保护开关。当前步骤可能完成读取或本地计算。紧急保护开关支持项目范围。
- 任务使用独立分支。同一应用进程内，同仓库的合并、发布及回滚共享锁，不同仓库独立。当前部署模式是单应用实例。
- 「当前阶段」和「执行状态」分开展示。开发异常仍保留开发阶段，异常视图也能列出该任务，因此异常数量不能再次加到阶段驻留数中计算任务总量。
- 项目有未结束任务时不能归档，包括尚未结束观测的发布任务和仍安排重新入池的废弃任务。归档产品线前需要先归档旗下项目。归档保留历史，不支持硬删除。
- 发布沿用现有 GitHub Tag / Release 流程；配置中的部署工作流不代表本版本已经执行生产部署。

## 升级已有数据

Flyway V3 为每条旧产品线创建 `<产品线ID>-default` 项目，迁移原仓库配置，并给任务、信号和费用记录补充项目归属。任务 ID、历史审计事件、证据内容及哈希不改写。已有任务没有新增节点执行记录的历史部分，仍通过原时间线和证据查看。

`LINE_ID`、`LINE_NAME`、`TARGET_REPO` 等旧环境变量继续用于首次初始化。已有产品线及项目以数据库保存的配置为准，重新启动不会覆盖页面修改。升级前应保留数据库备份。

## 主要接口

| 操作 | 接口 |
|---|---|
| 产品线列表 / 新增 | `GET /api/product-lines` / `POST /api/product-lines` |
| 产品线详情 / 编辑 | `GET /api/product-lines/{id}` / `PUT /api/product-lines/{id}` |
| 项目列表 | `GET /api/projects?productLineId={id}` |
| 新增项目 | `POST /api/product-lines/{id}/projects` |
| 项目详情 / 编辑 | `GET /api/projects/{id}` / `PUT /api/projects/{id}` |
| 校验仓库、分支及 CI | `POST /api/projects/{id}/connection` |
| 新增交付任务 | `POST /api/projects/{id}/tasks` |
| 项目任务 / 流水线 | `GET /api/tasks?projectId={id}` / `GET /api/board?projectId={id}` |
| 暂停 / 恢复任务 | `PUT /api/tasks/{id}/pause`，正文 `{"paused":true}` 或 `false` |
| 扫描项目 | `POST /api/projects/{id}/discovery/scan` |
| 候选列表 | `GET /api/projects/{id}/discovery/candidates` |
| 导入错误日志 | `POST /api/projects/{id}/discovery/logs`，正文包含 `title`、`log` |
| 候选转任务 / 忽略 | `POST .../candidates/{candidateId}/tasks` / `PUT .../candidates/{candidateId}/dismiss` |

旧 `/api/tasks` 和 `/api/signals` 接口允许显式传入 `projectId`。仅传 `productLine` 时，产品线下必须恰好有一个未归档项目，否则返回「请选择一个项目」。

## 验证

前端执行 `npm run verify`。后端执行 `mvn -f apps/server-java/pom.xml verify`，包含单元与集成测试，覆盖旧版本迁移、项目范围查重、暂停与预算隔离、并发名额、配置快照、候选证据和节点执行历史。
