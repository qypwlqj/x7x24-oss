# 发布目标与平台上线

项目配置中的 `releaseTarget` 明确任务交付到哪里。项目页的“项目配置 → 发布目标”可以选择：

| 目标 | 当前能力 | 完成含义 |
| --- | --- | --- |
| `github_release`（默认，兼容旧项目） | 创建 GitHub Release，校验标签指向合并提交，继续 CI 观测及收尾 | 仓库版本已发布；未验证应用或小程序上线 |
| `wechat_miniprogram` | 尚无微信上传、提审、审核结果和上线校验适配器 | 发布前停在“待配置发布”，不会用 GitHub Release 代替平台上线 |

例如：

```json
{ "config": { "releaseTarget": "wechat_miniprogram" } }
```

发布能力在合并前检查。不具备目标能力时，保留 `DELIVERED` 阶段，执行状态改为 `WAITING_CONFIGURATION`，停止调度，保存恢复位置。不会合并 PR、创建 Release、关闭 Issue 或发送发布成功／完成通知。若仓库版本已创建但尚未完成收尾，此时改为微信目标，仍会停止后续收尾并保留已有 Release 记录。

`deployWorkflow` 是历史预留字段，当前没有执行及平台结果核验实现。仅填写工作流名不能使微信能力检查通过，也不会自动触发该工作流。

发布目标变更立即作用于未完成任务，不能通过旧任务配置快照绕过检查。已停止任务需要显式恢复；恢复时重新检查当前能力，未就绪会返回具体原因，并保留停止状态。若用户确认交付范围只需要仓库版本，可显式切换到 `github_release` 后恢复原节点；这仍不表示小程序已上线。

任务接口通过 `delivery` 分别返回仓库版本状态与平台上线状态：

- `githubRelease`：`NOT_CREATED`、`CREATED`、`VERIFIED`。
- `deployment`：`NOT_REQUESTED`（只要求仓库版本）、`WAITING_CONFIGURATION`（目标平台能力未接入）。

`RELEASED` / `releasedAt` 保持兼容，含义为仓库版本发布；界面显示“版本已发布”。平台状态不会根据这个阶段、标签校验或 CI 成功推断为已上线。看板 `repositoryReleases` 统计仓库版本；`productionDeliveries` 仅代表已验证的平台上线，本版本没有对应适配器，数值为 0。已保存的历史评论和通知不追溯修改。

微信真实发布尚需独立接入，不能在当前界面通过勾选或工作流名声明“已上线”。未来接入时需要保存并核验目标平台的部署结果，才能增加真实上线状态。

验证：`ReleaseTargetIT` 覆盖配置缺失、工作流名不能冒充能力、旧快照不能绕过、已有 Release 不代表上线、配置变更后的恢复和目标校验；前端回归覆盖待配置进度、配置入口及仓库／平台状态分开展示。全部使用本地模拟外部接口。
