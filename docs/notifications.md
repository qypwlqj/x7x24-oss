# 任务通知

侧栏个人区域的设置图标打开“个人通知设置”。用户只填写收件邮箱，由系统统一发信。

## 用户配置

1. 保存收件邮箱，点击“发送验证码”，将邮件中的 6 位验证码填回页面。验证码 10 分钟有效，每次发送至少间隔一分钟，每个账号每小时最多发送 5 次，连续输错 5 次需重新发送。
2. 选择站内通知、邮件通知，以及当前工作区的全部项目或指定项目。
3. 选择通知事件并保存。默认订阅任务完成、正式异常和需要人工处理；发布成功、异常恢复、废弃按需订阅。
4. 发送测试邮件，通过“最近通知与发送记录”检查发送状态。顶栏铃铛打开通知中心，可查看未读消息、标为已读并跳转任务。

收件邮箱按账号保存，验证后才能启用邮件。偏好按工作区保存，发送前重新检查成员权限、订阅和邮箱。退出工作区、更换邮箱或取消订阅后，尚未发送的相关邮件将取消。只读成员可以管理自己的通知。

## 事件语义

- **任务完成**：发布校验成功，且上线观测和收尾均结束；对应 `feedbackDone` 首次变为 1。
- **发布成功**：进入 `RELEASED`，Release 已创建和校验，但仍处于观测阶段。
- **任务异常**：正式进入 `ANOMALY`；执行助手的普通失败重试不通知。
- **需要你处理**：`OWNER_NEEDED`、合并确认申请或新提交使旧确认失效。
- **恢复正常 / 废弃**：离开异常状态恢复执行，或进入废弃状态。

状态事件在任务更新事务内写入 outbox；人工处理提醒与对应审计事件在同一事务写入。持久化后台 worker 将事件扇出为用户通知，再独立投递邮件。网页关闭和应用重启不影响已落库队列。事件和收件人组合有唯一约束，避免重复创建投递记录。SMTP 成功接收但响应丢失时仍可能重复投递，不承诺严格的 exactly-once。

## 管理员发信配置

在后端部署环境中设置下列变量，重启后生效：

| 变量 | 用途 |
|---|---|
| `NOTIFICATION_APP_URL` | 用户可访问的前端根地址；未设置时使用 `X7_PUBLIC_URL`。不包含查询参数和 hash。 |
| `NOTIFICATION_FROM` | 经发信服务授权的发件地址 |
| `NOTIFICATION_SMTP_HOST` | SMTP 主机 |
| `NOTIFICATION_SMTP_PORT` | 默认 587 |
| `NOTIFICATION_SMTP_USERNAME` | 发信账号 |
| `NOTIFICATION_SMTP_PASSWORD` | SMTP 授权凭据，仅保存在部署环境变量中 |
| `NOTIFICATION_SMTP_STARTTLS` | 默认 true，要求 STARTTLS |
| `NOTIFICATION_SMTP_SSL` | 默认 false；465 隐式 TLS 场景设 true |
| `NOTIFICATION_WORKER_ENABLED` | 默认 true；测试或维护时可关闭后台投递 |

SMTP 连接、读、写均设 5 秒超时。仅对本机测试 SMTP 才关闭 STARTTLS；生产启用 TLS 并验证服务器身份。未配置发信服务时，站内消息正常生成，已经排队的邮件等待配置恢复。

邮件失败后以 1、2、4、8 分钟间隔重试，最多尝试 5 次，之后在发送记录中标记失败。投递租约为一分钟，进程崩溃后可重新领取。验证码在队列中加密存储，验证状态只保存带平台密钥的验证码摘要；投递结束后删除验证码密文。用户 API 不返回验证码、摘要或发信凭据。

## 页面操作归位

- 顶栏保留工作区运行模式、通知铃铛和紧急停止图标；停止启用后显示全局横幅及“查看保护”入口。
- 手动“运行一次”位于总览交付流水线，明确作用于整个工作区，不受筛选影响。
- “新增任务”位于任务列表和项目详情；项目页预选当前项目，任务列表预选当前筛选项目。
- 产品线、项目、日期筛选位于看板及任务列表，详情和设置页不显示。
- 总览展示看板数据更新时间，取消顶栏的常驻服务器时间。
