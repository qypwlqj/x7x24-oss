# 7x24 文案规范

适用于前端所有页面、提示、空状态、时间线，以及后端返回给用户的错误与失败原因。

## 原则
1. **先结果、后原因**：发生了什么 → 对我有什么影响 → 系统会怎么做 / 我能做什么。
2. **一句话一件事**：正文 ≤ 40 字；更长的规则放进「高级说明」折叠块。
3. **id 不进正文**：角色 id、配置版本号、配置键、环境变量放在灰色小字或「详情」里；正文写中文名称。
4. **不写实现动词**：继承、注入、拼进、fallback、dry-run、tick、payload 不出现在正文。
5. **英文只保留专有名词**：GitHub、PR、CI、Token、PRD、Issue；其他换中文。
6. **数字带上下文**：“已用 X / 上限 Y（单任务额度）”，不要只写“触顶”。
7. **报错可行动**：说明原因 + 下一步（按钮或链接）；不直接透出异常原文，原文放「详情」。
8. **同一概念只用一个词**，标准用词见下表，统一定义在 `apps/web/src/copy/terms.ts`。

## 标准术语
| 标准用词 | 不再使用 | 含义 |
|---|---|---|
| 返修 | Loop、qa_loop、迭代回流 | 测试没通过，回去重改 |
| 退回修改 | 驳回、reject | 验收没通过，打回重做 |
| 撤回上线 | 回滚 | 已上线的版本撤下 |
| 省钱模式 / 省钱线 | 降级、降级线、软阈值 | 预算快用完时改用便宜的模型、缩小范围 |
| 自动修复 | 自愈 | 系统自动重试 / 换方案 / 换模型 |
| 暂停使用 | 熔断 | 模型连续出错，先停一会儿 |
| 备用模型 | fallback、chain、兜底、档位链 | 主模型不行时依次切换 |
| 只记录模式 | dry-run、观察模式、演练 | 不改动仓库，只记录 |
| 真实执行模式 | 执行模式、execute | 真实创建 Issue / PR 并发布 |
| 紧急停止 | Kill switch | 立即暂停自动操作 |
| 配置版本 | 快照 | 每次保存配置生成的版本 |
| 基于内置角色 | 继承 | 在内置角色上加技能或要求 |
| 通过分 | 门槛、gate | 分数达到才算通过 |
| 评审结果 | 裁决 | 评审结论 |
| 流程步骤 | 节点、stage | 需求经过的环节 |
| 过程记录 | 证据、台账、链头 | 每一步留下的资料 |
| 立即运行一次 | 立即调度 tick | 手动触发一轮处理 |
| 执行助手 | Agent | 负责评审、开发、测试的 AI 助手 |
| 上线次数 | 迭代 | 一条需求从提出到上线算一次 |

## 守护测试
`apps/web/src/copy/copyLint.test.ts` 检查已整改文件的中文文案：禁用词、内部 id（`a.b.c`、`UPPER_CASE`）、非白名单英文都会让测试失败。
豁免：注释、`<code>…</code>`、行尾 `// copy-ok`（仅用于确实要展示原文的地方，如「详情」）。
后端对应的测试为 `UserMessageLintTest`，检查返回给用户的错误文案。
